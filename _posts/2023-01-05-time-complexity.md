## 간단한 소개

문제를 보자마자 코드부터 짜면 다 짜고 나서 시간초과가 난다.
**입력 크기(N)를 먼저 보고 어떤 알고리즘이 가능한지** 판단하는 기준이 시간복잡도다.

## 개념

- 입력 크기 N에 대해 연산이 몇 번 일어나는지를 **빅오(Big-O)** 로 표기한다.
- 상수와 작은 항은 버린다. `3N² + 5N + 2` → `O(N²)`
- 최악의 경우를 기준으로 생각한다.

## 원리

반복문이 몇 겹인지, 매번 범위가 얼마나 줄어드는지 보면 된다.

```python
for i in range(n):            # O(N)
    ...

for i in range(n):            # O(N²)
    for j in range(n):
        ...

while n > 1:                  # O(log N) - 절반씩 줄어듦
    n //= 2
```

증가 속도 비교

```text
O(1) < O(log N) < O(N) < O(N log N) < O(N²) < O(2ⁿ) < O(N!)
```

## 기준표

파이썬은 느려서 **1초에 약 2천만 번** 정도로 잡는다. (PyPy3는 훨씬 빠름)

| 데이터 크기 (N) | 허용 시간복잡도 | 대표 알고리즘 |
| --- | --- | --- |
| N ≤ 10 | O(N!), O(2ⁿ) | 순열, 조합, 완전탐색 |
| N ≤ 500 | O(N³) | 플로이드-워셜 |
| N ≤ 2,000 | O(N²) | 2차원 DP, 이중 for문 |
| N ≤ 100,000 | O(N log N) | 정렬, 힙, 이분탐색 |
| N ≤ 10,000,000 | O(N), O(log N) | 그리디, 투 포인터, 해시 |

## 파이썬 자료구조 연산 효율

| 연산 | 시간복잡도 | 비고 |
| --- | --- | --- |
| `list.append()`, `list.pop()` | O(1) | 맨 뒤 |
| `list.pop(0)`, `list.insert(0, x)` | O(N) | 맨 앞 → deque 쓰기 |
| `x in list` | O(N) | |
| `x in set`, `x in dict` | O(1) | 많이 찾을 땐 set |
| `list.sort()` | O(N log N) | |
