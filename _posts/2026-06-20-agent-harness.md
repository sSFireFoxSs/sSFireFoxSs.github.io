요즘 AI 관련 글을 보면 **하네스(Harness)** 라는 말이 계속 나온다.
처음엔 그냥 유행어인 줄 알았는데, Claude Code를 쓰면서 보니까 결국 "에이전트를 잘 쓰는 법"이 이 얘기였다.
공부한 내용이랑 직접 써보면서 정리한 걸 남겨둔다.

## 1. 하네스가 뭔가

> **에이전트 = 모델 + 하네스**
{: .prompt-info }

- **모델** : 다음에 무엇을 할지 생각하는 두뇌 (Claude 같은 LLM)
- **하네스** : 그 모델이 실제로 일을 할 수 있게 감싸는 모든 것

말에 씌우는 마구(harness)처럼, 힘은 모델이 내고 방향과 범위는 하네스가 잡아준다.

| 하네스 구성 요소 | 하는 일 |
| --- | --- |
| 실행 루프 | 생각 → 도구 호출 → 결과 확인 → 다시 생각 을 반복 |
| 도구 (Tools) | 파일 읽기/쓰기, 터미널 실행, 검색, 외부 서비스(MCP) |
| 컨텍스트 관리 | 무엇을 기억시키고 무엇을 버릴지 |
| 지침 / 메모리 | 프로젝트 규칙, 반복되는 설명을 미리 넣어두기 |
| 권한 / 안전장치 | 어떤 명령은 물어보고, 어떤 건 막기 |
| 검증 | 테스트, 린트로 결과를 스스로 확인 |

## 2. 왜 요즘 하네스 얘기가 많나

모델 성능은 다들 비슷하게 좋아졌는데, **같은 모델이어도 어떻게 감싸서 쓰느냐에 따라 결과 차이가 크게** 난다.
그래서 "프롬프트를 잘 쓰자"에서 **"모델이 일하는 환경을 잘 설계하자"** 로 관심이 옮겨간 느낌이다.

- 프롬프트 엔지니어링 : 한 번의 질문을 잘 쓰기
- 컨텍스트 엔지니어링 : 모델이 보는 정보를 잘 고르기
- 하네스 엔지니어링 : 도구, 규칙, 검증, 권한까지 일하는 환경 전체를 설계하기

## 3. Claude Code에서의 하네스

Claude Code 자체가 하나의 하네스이고, 그 위에 내가 설정을 얹어서 나한테 맞게 만드는 구조다.

### CLAUDE.md - 프로젝트 지침

프로젝트 루트에 두면 대화가 시작될 때마다 읽는다. 매번 설명하던 걸 여기에 적어둔다.

```markdown
# 프로젝트 규칙
- Python 3.12, 패키지 관리는 uv
- 테스트: `uv run pytest`
- 커밋 전에 `ruff format .` 실행
- API 응답 형식은 docs/api.md 참고
```

> 길게 쓰면 오히려 중요한 걸 놓친다. **꼭 필요한 규칙만 짧게.**
{: .prompt-tip }

### Skills - 반복 작업을 묶어두기

자주 하는 작업 절차를 `SKILL.md`로 만들어두면, 필요할 때 Claude가 알아서 불러서 쓴다.

```markdown
<!-- .claude/skills/api-test/SKILL.md -->
---
name: api-test
description: FastAPI 엔드포인트를 추가하거나 바꿨을 때 테스트를 작성하고 실행한다
---
1. tests/ 아래에 같은 이름의 테스트 파일이 있는지 확인
2. 정상 / 422 / 404 케이스를 작성
3. `uv run pytest` 로 실행하고 실패하면 고친다
```

### Subagents - 일 나눠 맡기기

탐색이나 리뷰처럼 따로 떼어낼 수 있는 일은 서브에이전트에 맡긴다.
서브에이전트는 **자기만의 컨텍스트**에서 일하고 결과만 돌려주기 때문에 메인 대화가 덜 지저분해진다.

```markdown
<!-- .claude/agents/reviewer.md -->
---
name: reviewer
description: 변경된 코드를 읽고 버그와 개선점을 찾는다
tools: Read, Grep, Glob
---
변경된 파일만 읽고, 버그 가능성이 높은 순서로 정리해서 알려준다.
코드는 직접 수정하지 않는다.
```

### Hooks - 무조건 해야 하는 일은 자동으로

"코드 수정하면 포맷터 돌려줘"를 매번 말하는 대신, 훅으로 걸어두면 **모델이 까먹어도** 실행된다.

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [{ "type": "command", "command": "ruff format ." }]
      }
    ]
  }
}
```

지침(CLAUDE.md)은 "부탁"이고, 훅은 "강제"라고 생각하면 이해가 쉽다.

### MCP - 외부 도구 연결

노션, 깃허브, DB 같은 외부 서비스를 도구로 붙이는 표준.
연결해두면 "이슈 목록 보고 정리해줘" 같은 요청을 직접 처리한다.

### 권한

명령마다 허용 / 확인 / 거부를 정할 수 있다.
`rm`, `git push` 같은 건 항상 물어보게 해두는 게 마음이 편하다.

## 4. 내가 쓰는 방식

써보면서 정착한 흐름.

1. **계획 먼저** : 바로 코드 짜라고 하지 않고 계획 모드로 어떻게 할지 먼저 보게 한다
2. **작게 나눠서** : 기능 하나씩 요청하고 확인
3. **검증 수단 주기** : "테스트 돌려서 통과할 때까지"처럼 스스로 확인할 방법을 알려준다
4. **컨텍스트 정리** : 주제가 바뀌면 `/clear`로 새로 시작
5. **반복되면 하네스로** : 두 번 이상 설명한 건 CLAUDE.md, 스킬, 훅으로 옮긴다

> 결국 에이전트를 잘 쓴다는 건 **"잘 시키는 것"** 보다 **"잘 일할 수 있는 환경을 만들어주는 것"** 에 가깝다.
{: .prompt-tip }

## 정리

| 개념 | 한 줄 |
| --- | --- |
| 하네스 | 모델이 일하게 감싸는 모든 것 (루프, 도구, 컨텍스트, 권한) |
| CLAUDE.md | 매번 읽는 프로젝트 지침 |
| Skills | 필요할 때 불러 쓰는 작업 절차 |
| Subagents | 따로 맡기는 일꾼, 컨텍스트 분리 |
| Hooks | 무조건 실행되는 자동화 |
| MCP | 외부 서비스 연결 |

다음에는 실제로 써본 스킬들을 하나씩 리뷰해볼 생각이다.
