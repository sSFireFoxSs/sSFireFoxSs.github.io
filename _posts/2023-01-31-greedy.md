## 간단한 소개

**매 순간 가장 좋아 보이는 것**을 고르는 방법.
코드는 짧은데 "이렇게 골라도 되나?"를 판단하는 게 어렵다.

## 개념

- 지금 당장 최선인 선택을 계속 하다 보면 전체도 최선이 되는 경우에만 쓸 수 있다
- 성립 조건
  - **탐욕적 선택 속성** : 지금의 최선 선택이 나중 선택에 영향을 안 줌
  - **최적 부분 구조** : 부분 문제의 최적해가 전체 최적해로 이어짐
- 대부분 **정렬 + 반복문**으로 끝난다

## 원리

### 되는 경우 : 거스름돈 (500, 100, 50, 10원)

큰 동전이 작은 동전의 **배수**라서 큰 것부터 쓰는 게 항상 최선.

```text
1260원 → 500×2 + 100×2 + 50×1 + 10×1 = 6개
```

### 안 되는 경우 : 동전이 1, 3, 4원이고 6원 만들기

```text
그리디 : 4 + 1 + 1 = 3개
정답   : 3 + 3     = 2개
```

배수 관계가 아니면 그리디가 틀린다 → 이럴 땐 **DP**.

> 그리디로 풀기 전에 **반례가 있는지** 작은 예시로 꼭 확인하기
{: .prompt-warning }

## 코드

### 11047 동전 0

```python
n, k = map(int, input().split())
coins = [int(input()) for _ in range(n)]

cnt = 0
for c in reversed(coins):    # 큰 동전부터
    cnt += k // c
    k %= c
print(cnt)
```

### 11399 ATM (오래 걸리는 사람을 뒤로)

```python
n = int(input())
p = sorted(map(int, input().split()))

total = 0
acc = 0
for t in p:
    acc += t
    total += acc
print(total)
```

### 1931 회의실 배정 (빨리 끝나는 회의부터)

처음엔 시작 시간 순으로 했다가 틀림. **끝나는 시간**이 기준이다.

```python
import sys
input = sys.stdin.readline

n = int(input())
meetings = [tuple(map(int, input().split())) for _ in range(n)]
meetings.sort(key=lambda x: (x[1], x[0]))   # 끝 시간, 같으면 시작 시간

cnt = 0
end = 0
for s, e in meetings:
    if s >= end:
        cnt += 1
        end = e
print(cnt)
```

시작 시간도 같이 정렬하는 이유 : `(2, 2)`처럼 시작과 끝이 같은 회의가 있으면 순서에 따라 답이 달라짐.

### 1541 잃어버린 괄호

`-` 뒤에 나오는 건 전부 괄호로 묶어서 빼면 최소가 된다.

```python
parts = input().strip().split('-')
ans = sum(map(int, parts[0].split('+')))
for p in parts[1:]:
    ans -= sum(map(int, p.split('+')))
print(ans)
```

## 시간복잡도 / 효율성

- 정렬이 들어가면 **O(N log N)**, 아니면 대부분 **O(N)**
- 빠르고 코드도 짧지만 정당성 증명이 안 되면 틀린 답이 나옴
