11월 13일 종합설계 졸업작품전시회를 끝으로 6개월 동안 붙잡고 있던 졸업작품을 마무리했다.

## 프로젝트 개요

> 달린 거리 · 경로 · 시간을 GPS로 기록하고, 친구와 **목표 거리 · 마감일 · 벌칙**을 걸어 대결하는 러닝 앱
{: .prompt-info }

| 항목 | 내용 |
| --- | --- |
| 기간 | 2024.05 ~ 2024.11 (약 6개월) |
| 인원 | 1인 |
| 발표 | 종합설계 졸업작품전시회 (2024.11.13) |
| 기술 | Flutter, Firebase (Auth · Firestore · Storage), Kakao SDK, Google Maps, Geolocator |
| 규모 | 화면 17개, Dart 약 4,400줄 |

## 주요 기능

| 기능 | 설명 |
| --- | --- |
| 기록 | GPS로 달린 거리 · 경로 · 시간 기록 |
| 친구 | 친구 요청과 수락 |
| 대결 | 목표 거리 · 마감일 · 벌칙을 걸고 달성률로 겨룸 |
| 로그인 | 이메일 / 카카오 로그인 |

## 핵심 문제

GPS 기록이 곧 승패라서, **휴대폰이 보내는 위치 · 계정 데이터가 틀리면 앱 전체가 무너진다.**
그 데이터를 믿을 수 있게 만드는 게 이 프로젝트의 핵심이었다.

## 잘한 점 - 문제를 이렇게 해결했다

| 문제 | 원인 | 해결 |
| --- | --- | --- |
| 지도가 뜨지 않았다 | 위치 꺼짐 · 권한 거부 · 영구 거부 등 원인이 여러 개, 원인마다 사용자가 할 일도 다름 | 원인별로 다른 안내, 권한은 한 번 더 요청, 현재 위치를 받은 뒤 지도 표시 |
| 굽은 길이 직선으로 그려졌다 | 좌표가 드문드문 들어와 그 사이 길 정보가 없음 | **5m 움직일 때마다** 좌표를 쌓아 경로를 그리고, 좌표 간격을 더해 거리 계산 |
| 한 사람이 두 사람이 됐다 | 카카오 로그인 사용자가 앱 회원 정보와 연결되지 않음 | **이메일을 고유 키**로 기록 · 친구 · 대결 통합, 이메일이 없으면 저장하지 않고 안내 |

## 아쉬운 점

| 아쉬운 점 | 내용 |
| --- | --- |
| 대결 거리 중복 합산 | 대결 현황 화면을 열 때마다 거리가 또 더해지는 버그 (0.57km → 1.14km) |
| 카카오 계정 처리 | 카카오 사용자를 연결하면서 비밀번호를 임시 방식으로 처리 → 보안상 취약 |
| 정리 안 된 코드 | 안 쓰는 패키지(Realtime Database)와 만들다 만 알림 기능이 남아 있다 |
| 마감 직전 몰아치기 | 설계 없이 기능부터 붙여서 전시 직전까지 대결 · 로그인 · 러닝 화면을 계속 수정 |
| 테스트 없음 | 직접 뛰어보는 것 말고는 확인할 방법이 없었다 |

## 다시 한다면

- 데이터 구조(누가, 언제, 어떤 값을 바꾸는지)를 **먼저 설계**하고 시작하기
- 거리처럼 중요한 값은 **한 곳에서만** 바꾸게 만들기
- 로그인 연동은 임시방편 말고 제대로 된 방식으로
- 작게라도 **끝까지 동작하는 버전**을 먼저 만들고 기능 늘리기

## 마무리

Flutter도 Firebase도 처음이었고, 기획부터 개발, 전시까지 혼자 해야 해서 쉽지 않았다.
막히면 찾아보고, 친형한테 물어보고, 그래도 안 되면 방법을 바꿔보는 과정을 6개월 동안 반복했다.
부족한 점이 많지만 처음으로 **혼자 기획부터 앱 완성, 전시까지 끝까지 해봤다**는 게 가장 큰 수확이다.
